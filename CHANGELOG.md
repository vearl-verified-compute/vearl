# Changelog

All notable changes to the testnet software are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/);
versions are testnet releases, not stable releases.

## [0.1.0] - public testnet (launch: 2026-10-23 16:00 UTC)

First public release of the source code.

### Protocol
- Proof of useful work over int8 tile products (NoisyGEMM-T) with verification by tile recomputation, Merkle openings, Freivalds tests and
  single-cell fraud proofs.
- Compute market with escrow, auctions, bonds, data availability and fraud proofs; job types: tiled products, tensor programs
  (CNN, residual blocks, transformers, language-model steps), multi-layer inference, level-2 jobs (Monte Carlo, 3D rendering).
- ASERT difficulty retargeting (30 s target), atomic reorganizations, optional MESS protection, header v2 with account root and balance
  proofs, header-based light client, SLH-DSA post-quantum accounts (optional).
- Noise XX encrypted peer protocol with pinned node keys.

### Release candidates
- rc25: **the miner updates itself, but only to a release signed by the Vearl release key, and only to a newer one** (`vearl-miner`, `src/updatesig.rs`, `src/bin/release_sign.rs`). At each start the miner reads `https://vearl.org/release/latest.json` (5 s timeout, silent when offline). A newer release (strictly greater tag: a signed old manifest replayed by someone is not an update) is downloaded to a temporary file, checked against its SHA-256, run in the same window and deleted when the miner closes: nothing is installed and the program on disk never changes. Each platform entry (`win64`, `linux64`, `hiveos`) carries an Ed25519 signature (`sig`) of `vearl-update/1|tag|platform|url|sha256`; the public key is fixed in the miner at build time (`VEARL_UPDATE_PUBKEY`) and a build without it never updates itself, so a hash written next to the address cannot be replaced together with it by whoever controls the web server. `vearl-release-sign keygen|pubkey|sign|verify` is the maintainer's tool; the private key stays off the repository and off every server. `--no-update` skips the check; `--devnet` never checks. Tests: `updatesig` (3) and `only_a_newer_manifest_signed_by_the_release_key_is_an_update`.
- rc25: **AI jobs reach the miners that hold the models** (`docs/21`). On top of the relay (below): replies of operations are deflated (`GetOpsBoxZ`; MiniLM 4 MB per text instead of 180, BGE 24 MB instead of 800, ViT 33 MB per photo, GPT 9 MB per word), a link test (`GetProbe`, `vearl-cli probe` and `has-model`) and a loopback-only `/api/workers` on the relay node let the job service choose, for each kind, only the miners whose link is fast enough (`deploy/ml/routing.py`, `vearl-ml.py --auto-workers`); the service offers a kind only while such a miner is online. New kinds `minilm` and `bge` (text embeddings, verified on chain). The model packs of the testnet are now five (GPT, ViT, Qwen3-Embedding, MiniLM, BGE: 815 MiB, release `models-2`) and `vearl-miner` fetches them from there. The CIFAR ResNet-20 is retired (32x32 photos are too small to be useful); a 224x224 ResNet trained on a fifth of ImageNet reached only 13-18 % top-1 and is not offered, ViT (DeiT-Tiny) stays the image kind.
- rc25: **a pool no longer bans an address for shares that miss the share target** (`src/pool.rs`). A share below the target (`E_LOW_DIFF`) costs the pool nothing and happens when a client is a little slow to apply a new target; it counted 5 strikes of 25 and the ban (10 minutes, per IP address) also hit every other miner behind the same address (rig farms, home routers), who then saw `refused by the pool: banned` in a loop. Invalid nonces and duplicates still count. Deployed on the official pool on 2026-10-24.
- rc25: **the pool audit no longer calls a pool fraudulent for a block it does not list** (`src/poolpoints.rs`): a block mined through a solo port under the pool's address is on the chain but is never in the PPLNS ledger by design, so `hidden_block` and `undocumented_block` are `suspect` (a person checks with the pool), not `fraud`.
- rc25: **the pool audit tolerates the stale loss that every pool shows at 10-second blocks** (`tools/audit_pools.py`, `relax_stale_loss`). The work-versus-blocks test counted as found only the blocks that stay on the chain, so a pool whose ledger claims more work than its blocks (shares credited on a job that had just become stale, blocks that lost the race at their height) looked "suspect" on the second day of the testnet: the two largest pools (two different pool programs, 48 % of the blocks each) showed the same ratio, 1.23 claimed per block found, the small pools 1.0. The test is run again with 30 % of the claimed work allowed to be lost; a pool that claims more than that stays suspect, "the ledger hides work" and every other finding are unchanged. New tests in `tools/test_audit_relax.py`. The audit program itself (`src/poolpoints.rs`) still has the strict test: to be aligned in the next build.
- rc25: **AI jobs can reach a miner behind a home router** (`docs/21` section 4 bis). The relay now also carries the requests of an AI job on a model that the miner holds in advance: `HasModel`, the input of a job (`PutProgRef`, 1 MiB), at most two extra model blocks per `PutModel` (the mean vector of a text), and the outputs of operations (`GetOpsBox`, `GetOp`, replies up to 9 MiB), with their own limits (16 at a time, 4 per worker). `vearl-cli` asks again when the relay is busy and works with fewer requests at a time through a relay. No consensus or genesis change; a worker of an older release answers "request not relayable". Measured on a local network with the regenerated ResNet-20, MiniLM and BGE-base: every job verified, every output identical to the independent engine; traffic about 3.6 MB per photo, 180 MB per MiniLM text, 800 MB per BGE text (everything is fetched to verify it). New test `the_requests_of_an_ai_job_travel_through_the_relay`.
- rc24: **the pool audit no longer calls a pool suspect because of the first minutes of a network** (`tools/audit_pools.py`). The work-versus-blocks test assumes a block difficulty that is about constant over the day; at the start of vearl-testnet-1 it moved by a factor of 1,000 in minutes while blocks were one second apart, so honest pools lost most of the blocks they found as stale and showed "claimed work too high". When the target of the chain (read from the blocks of the rewards run, never from the pool's document) moved by more than x4 during a day, that finding is now information, with the reason written in the report; the verdict and the epochs are recomputed, every other check stands. `blocks.json` now carries the target of each block. New tests `tools/test_audit_relax.py`.
- rc24: **the paid-work multiplier of the testnet rewards cannot be farmed with jobs nobody else wants** (`tools/testnet_rewards.py`, docs/19; reported by an outside reviewer). A block that carried paid work still counts 1.5 points, but not when the miner is the client of that job, not beyond 20 blocks of the same job, and not twice for the same operation, layer or product of a job; such a block counts 1 point. The client of each job is read from the node and saved in `blocks.json`, so the result stays reproducible. New tests `tools/test_paid_work_rules.py`.
- next (rc23): **the AI models are installed on the miners in advance, a client no longer sends them.** The weights of a model are too large to travel with every job (models of tens of billions of parameters are planned), so the miner holds them and a job only names the model. `vearl-miner` downloads the model packs (`NAME.vblocks`, about 650 MiB for the three models of the testnet) in the background at start, checks them against a SHA-256 list and the node (`node --models-dir DIR`) loads them into its registry, so `HasModel` answers "present" and the client uploads nothing; new packs put in the folder are picked up every 30 s and the packs do not count in the upload cap. New: `vearl-miner models [--from FOLDER_OR_URL]`, `--no-models`, `"models": false` in `miner.json`, `tools/make_model_pack.py`. A model that is not installed works as before (the client sends it once). The protocol and the blocks are unchanged.
- next (rc22): **paid jobs next to the pool.** A miner in pool mode can now also take the paid jobs of the compute market (AI models, computations). A pool mines the Native Work only, and the block rules require the worker of a job to be the miner, so the machine runs a Vearl node as a worker only (`node --worker --no-native`, new option: it never mines Native blocks) next to `vearl-poolminer`, on the same GPU, with the user's wallet: the wizard asks "Also take paid jobs?" when a wallet is given (default yes), the wallet address is the payout address, the password is asked at each start (Enter skips the jobs for that session and the pool keeps mining) or remembered if chosen; a job pays the wallet directly and needs a few VRL in it for the bond. `--no-jobs` turns it off for one run. The weights of a model are not bundled: the client sends them once to the worker with its job. Tested on a local devnet with a real pool: shares accepted by the pool and a matrix job and a model inference settled by the same miner process. HiveOS stays pool-only. New test `a_worker_only_node_mines_no_native_block_but_still_computes_jobs`.
- next (rc21): **the GPU miner is about three times faster at the real size** (n = 1024, the public testnet). The miners copied every jackpot of every batch back from the card and scanned them one by one on the CPU (a batch was only 8 sigmas, about 0.3 ms of GPU work), so the card was idle more than half of the time. The GPU now compares each jackpot with the target itself (the same rule as `meets_target`, first 8 bytes big-endian) and returns only the winners; the batch is 32 sigmas at this size; the noise kernel writes 4 tiles per warp with 8-byte stores; the folding of the accumulators rotates once instead of twice (`rotl(a, r) ^ rotl(b, r) = rotl(a ^ b, r)`) and keeps its schedule incrementally; each GPU runs two mining threads, each with its own CUDA stream (`VEARL_GPU_WORKERS=1..4`, default 2), so the card is never idle between two batches. Measured on an RTX 4070 SUPER against a local pool with the public parameters: 13.1-13.7 k sigma/s (rc20) to 41-44 k sigma/s, no share refused. The work, the consensus rules and the blocks are unchanged (new test `gpu_matches_cpu_at_the_real_testnet_size`, and `gpu_hits_equal_scanning_the_full_batch`).
- next (rc21): **`vearl-pool` saves its state when it is stopped.** A stop or a restart (SIGTERM, Ctrl+C) used to bring the pool back to its last periodic save, up to 30 seconds old, so blocks found just before were missing from the hourly ledger. Reported by a pool operator. The pool now saves and exits.
- next (rc21): **the wallet retries a registration e-mail cut by the network and says what happened.** A connection closed during the TLS handshake ("unexpected end of file") or a timeout is tried three times; the error names the cause in English instead of the text of the operating system.
- next (rc21): **registration by e-mail reads more webmails** (`tools/process_registration_mail.py`): a value written on the line under its label (`signature:` alone, the hex below it) and blank lines inside the message are accepted. The signature is still verified.
- next (rc21): **HiveOS: the archive is named `vearl-<version>.tar.gz`** (for example `vearl-0.1.0rc21.tar.gz`): HiveOS compares the Miner name with the name of the file and the archive holds the folder `vearl/`. The Miner name to type is `vearl`.
- next (rc21): **the servers hold a crowd at the launch** (`docs/06` section 3 septies): a one-second micro-cache of the node's API and of the job gateway's reads in nginx (the node's HTTP server answers 64 connections and 16 long polls at a time), the explorer polls the status instead of long-polling, more nginx connections, the same for the pool's statistics and `--max-conns 5000` on the pool. Measured: 3000 visitors at once on the pages and on the explorer's API, no error.
- next (rc21): **the testnet goes on line by itself at the launch time** (`deploy/launch/`, `docs/06` section 3 sexies): a timer on the seed switches the explorer to the real node, pays the service wallet from the faucet wallet, starts the job gateway and opens `/compute/` and `/faucet/` once the chain runs, with a verification and an undo for every stage; `deploy-site.sh` keeps the testnet on line after that. Found and fixed while rehearsing it: the unit of the public gateway had a literal `\n` in its command line (the service could not start), and the explorer still said 'target 30' for the block time (it is 10 s).
- next (rc21): **solo port on the official pool.** `vearl-pool --solo-listen ADDR [--solo-fee 1.0]` opens a second port (3366 on the official pool) where a worker mines solo through the pool, without running a node: a block it finds pays the whole reward, minus the fee (1 %), to its address; its shares count for the points like every verified share but stay out of the PPLNS window of the main port. Same protocol, no change for miners, wallets or nodes (a miner only needs the other port: `vearl-miner` `--pool HOST:3366`). Test in `tests/pool.rs`, `docs/16` section 6.
- next (rc21): **registration by e-mail reads three lines glued into one** (`tools/process_registration_mail.py`): Yahoo and some phones lose the line breaks of a mail sent by hand, leaving `address: ... message: ... signature: ...` on one line, which was dropped; the signature is still verified. Installed on the server on 2026-10-18.
- next (rc21): **a worker drops the run of a job it no longer holds.** A worker that mines can see its claim of a model job reorganised away: the job is then open again or held by another worker, but the worker kept serving the data it had computed, so two workers answered for the same job (the test `model_jobs_spread_over_the_workers_that_hold_their_data` failed by chance, about one run in five on a loaded machine; 0 in 75 after the change). The worker now drops such a run at its next turn; no protocol change.
- rc20: **mining-pool audit and credit, two fixes reported by a pool operator.** (1) A block the pool found and that was later orphaned stayed in the points document and the audit called it `phantom_block` (fraud): an honest pool would have been excluded after its first orphan, which is normal with blocks every 10 seconds. The audit now treats a listed block that is not on the chain as an orphan (informational, it earns nothing because the points come from the blocks of the chain) and only asks a person to look when more than a third of the blocks listed are off the chain; a block far above the top of the chain is still fraud. The pool removes an orphan from the documents that are not published yet and lists only the blocks still on the main chain when it closes an epoch. (2) After a difficulty drop a share could be credited at the previous session target, harder than the network target of its job, and the audit called it fraud. The pool now credits a share at the hardest target it meets but never harder than the target of its job, and the audit no longer treats a valid harder credit as a finding (the recomputation still catches a share that does not reach its target). The audit change alone protects the pools that run an older release.
- rc19: **pool or solo, chosen by the miner.** `vearl-miner` (Windows, Linux) asks at its first start how to mine: POOL (the official pool named by `network.json`, only a payout address needed, no node and no wallet password; no paid jobs and no Quantus in this mode) or SOLO (the node mines alone, as before). `vearl-miner pool` / `vearl-miner solo` switch and remember the choice, `--mode`, `--pool`, `--address` and `--worker-name` start one run without any settings file, `vearl-miner check` also tests the pool. The release adds `start-pool` and `start-solo` shortcuts and a `pool` entry in `network.json`. The HiveOS package mines in the pool by default (Pool URL field of the flight sheet, empty or `pool.vearl.org:3333`; payout address in the wallet template, no set-up on the rig) and in solo mode with `solo` as the Pool URL; the Hive stats report the pool's accepted/refused shares. Existing settings files keep mining solo.
- next (rc17): **job site: text embeddings with Qwen3-Embedding-0.6B** (`embed` kind of the ML service `deploy/ml/vearl-ml.py --embed`, catalogue and pre-launch `info.json` of the gateway, form, similarity table and details in `site/assets/compute.js`). The public site stays in pre-launch mode: the kind is shown, nothing can be created.
- next (rc17): **HiveOS package** (`deploy/hiveos/`): a custom-miner archive for mining rigs (flight sheet, one-time wallet set-up with `setup.sh`, settings kept in `/hive-config/vearl`, speed and temperatures reported to HiveOS, `gpus=` and `max_jobs=` options). Built from the Linux release; tested with a simulated Hive environment, not yet on a real HiveOS rig. See `docs/15` section 4 quinquies.
- rc18: **wallets and miners are no longer refused by a busy node.** A node accepted at most 24 inbound connections in total, 2 per IP address and 4 per /16 network, and counted the short requests of wallets and tools like peers: a wallet could not connect to the seed from an address that already hosted two nodes or miners (a rig farm, a home with two machines), or from a network that already had four connections to it, and a seed with 24 peers refused every new node, which then had no address to try. Now the limits apply to PEERS only (nodes that exchange blocks), wallets and tools are bounded by 256 connections in total and 16 per address, a peer that does not fit gets the list of known addresses before it is closed, refusals are logged (one line every 10 s), and a node takes `--max-inbound`, `--max-per-ip`, `--max-per-subnet` and `--max-conns` (a public seed raises them). The password prompt of the miner and of the wallet tool now says that typing is hidden (nothing appears, not even stars). No consensus or protocol change: rc17 and rc18 nodes interoperate, the genesis file and its hash do not change.
- rc16.2: **registration for the rewards by hand.** The Copy button of the wallet window gave the three lines without their labels (`address:`, `message:`, `signature:`), and the server script dropped such mails: someone whose network blocks the automatic e-mail (port 465) and who sent the lines by hand was not registered. The button now copies the labelled lines, and `tools/process_registration_mail.py` also accepts the three lines without labels (recognised by their shape; the signature is still verified).
- rc16.1: **mining rigs: every GPU works.** Up to rc16 only the first GPU of a machine mined: the launcher started the Quantus miner with `--gpu-devices 1`, and the Vearl mining loop used GPU 0 only (reported on Discord: a rig of 4 GPUs, one at 100 %, three idle). Now `vearl-miner`, `node` and `vearl-poolminer --gpu` use every NVIDIA GPU of compute capability 8.0 or newer: one worker per GPU, the batches of sigmas of a block search are handed out in turn (a faster card does more of them, models can be mixed), a pool job's nonce range is shared in interleaved batches, and the Quantus miner is started without `--gpu-devices` (one worker per CUDA GPU). `CUDA_VISIBLE_DEVICES` restricts the GPUs for everything, `VEARL_GPUS` (CUDA indices) for Vearl mining only. The CUDA code keeps one context per device (`vearl_gpu_new_on`, per-device set-up). No consensus or protocol change: blocks found by several GPUs are ordinary blocks. Paid jobs still run on one GPU. See `docs/15` section 4 quater.
- next (rc17): **four new operations for the Qwen3 models**, in preparation for the first embedding model of 0.6 billion parameters (consensus change, `docs/07` section 12.2: `RmsNorm{x, len, group, shift}` (RMS normalisation with 4 fractional bits in the root, optionally per group of rows: the QK-norm; `shift` widens the output range for the heavy-tailed queries and keys), `MulT{a, b, shift}` (element-wise product of two tensors: the SwiGLU gate) `MulW{x, w, shift}` (element-wise product with a weight table: the rotary position embedding), with a new fraud proof `MulW`, and `CausalSoftmaxS{x, len, l, fine, scale}` (causal softmax whose exponent step is 2^scale times coarser: the attention logits of the Qwen3 models span more than 20 nats relative to the sink token, the 8-bit score tensor of `CausalSoftmax` only 11); the others reuse the proofs of `LayerNorm`, `Add` and `Softmax`. Written in Rust and, independently, in Python (`vearl_ref.py`, `prog_ref.py`); the program vectors now hold 616 blocks (seven more programs, two honest and five wrong); differential fuzz Rust against Python 3,000 decisions and conformance of 2,996 random programs, 0 divergence. Every node must run rc17. Workers also accept up to 1,024 registry blocks (was 512) and a 2 GiB deposit file, for the 528 blocks of a 0.6 B model.
- next (rc16): **jobs find a worker more often.** Public level-2 jobs (Monte Carlo, rendering): a claim now lasts 30 minutes (15 x `serve_secs`); if the worker has not published by then, any other worker can claim the job again, and the first one loses its bond, instead of the job waiting for its deadline (consensus rule, `docs/10`; the genesis file and its hash do not change; every node must run rc16). Tensor-program jobs: `vearl-cli infer NODE WORKER1,WORKER2,...` deposits the model with several workers, which share the jobs (each takes at most 16 at a time, drops a claim that lost the race at once, and the client finds the worker that serves each result).
- next (rc15): **block time 10 s** (was 30 s), so that a verified job is paid in about 70 s instead of about 4 minutes (measured: 7 blocks per job, 225 s with 29-s blocks, 37 s with 5.5-s blocks). The emission per year does not change: `R0` is 6.66666666 VRL per block (20 VRL per 30 s, rounded down), `HALVING` 3,153,600 blocks (365 days), `TAIL` 0.16666666 VRL; `EPOCH_LEN` 300, `LWMA_N` 90, `SNAP_EVERY` 48 and the default pool confirmations 30 keep the same durations. The dispute window stays 300 s and 10 blocks, whichever is longer. The published genesis (hash `46c57f50…`) is unchanged; ASERT corrects its initial target (calibrated for 30 s) within the first hour. `vearl-cli` job deadlines are expressed in seconds. Test vectors regenerated and re-validated by the independent Python implementations; simulations of `docs/13` re-run for 10-s blocks.
- next (rc14), fee protection (`docs/17`): the development-fee constants (address, percentage, digest) are generated at build time from a secret that changes with every release (`deploy/release/fee_secrets.py`), so a script that patches one release finds nothing in the next; the `fee-obf` maintenance command is gone; the fee miner's command line, the scheduler's time counters and the percentage are cross-checked at run time (any mismatch switches all Quantus mining off); the beacon also carries the time counters and the destination digest; the auditor flags `wrong_fee_dest` and `low_declared_split`, tightens its thresholds to what an honest miner measures, and publishes `fee-stats.json`; an address that uses the add-on without the fee is not eligible for the testnet rewards (`docs/19`). The seed must run rc14 before the miners (the beacon changed).
- next (rc14), pools: **`vpool/2`**, the points of a pool's blocks go to its miners and the pool cannot cheat quietly (`docs/16` section 13, `docs/19` section 3 bis). The pool publishes a signed hourly ledger (work of every miner, blocks found, Merkle root of all the shares, chained to the previous document) and sends each miner signed receipts; `vearl-pool-audit` and `tools/fetch_pool_bundle.py` check the documents, the shares (recomputed), the chain, the receipts and the work against the blocks; `tools/testnet_rewards.py --pools` shares the points of registered pools by verified work and ignores fraudulent hours. `vearl-poolminer` keeps its receipts in `pool-receipts.jsonl` and prints the testnet points it has earned; a pool shows the points of an address (`/api/points/miner/<address>`, its page, `--leaderboard FILE` for the official figure). `vpool/1` miners still work and earn payouts, not points.
- next (rc14): **relay** for the audit of miners behind a home router (`docs/21`). A seed started with `node --relay` forwards read requests to a worker over the worker's own outgoing connection; `vearl-cli` accepts `relay://SEED:9000/l2:JOB` and `relay://SEED:9000/acct:ACCOUNT` as worker addresses; the public gateway tries the relay first. New peer messages appended to the protocol, no consensus or genesis change; stopping a node now closes its connections.
- next (rc13): **Vearl Wallet** (`vearl-wallet-gui`, Windows and Linux): the wallet with a window, in the Vearl look. Balance, activity,
  receive (address and QR code), send (standard or post-quantum signature, with a summary and the password before anything leaves),
  registration for the testnet rewards, sign and verify messages, recovery words, password change. Same wallet files as `vearl-wallet`:
  the keys are opened only for the moment of an action. A six-step creation (pointer randomness mixed with the system generator, 24 words
  that decode and hide again by themselves, a check of three words, the file written and read back), animations throughout (reduce-motion
  setting), refusal to sign for a node on another network (genesis check), new-recipient warning, slow-down after wrong passwords, lock after
  inactivity, recovery words hidden from screen capture on Windows, a demo mode for recordings (`--demo`). See `docs/20`.
- rc12: `vearl-wallet register` signs the testnet-rewards registration and, after confirmation, e-mails it to `register@vearl.org`
  (TLS, public send-only account that can write to that address only); a server script (`tools/process_registration_mail.py`) checks the
  signatures and publishes `registered.json`. `--print-only` shows the three lines to send by hand. See `docs/19`.
- rc11: `vearl-wallet sign` and `vearl-wallet verify` (signature proving ownership of an address).
- rc10: the command-line tools print a help text and, on Windows, wait for Enter instead of closing when double-clicked.

### Programs
- `node`, `vearl-miner` (wallet assistant, mines Vearl with the whole GPU), `vearl-cli`, `vearl-wallet` (24 words, Argon2id),
  `vearl-genesis`, `vearl-faucet`, `vearl-pool` and `vearl-poolminer` (pool protocol `vpool/1`).
- Optional Quantus add-on for the miner (separate download, off by default); its development fee and audit are described in `docs/17`.
- CUDA kernels for Ampere and newer GPUs, bit-for-bit identical to the CPU code; Windows and Linux builds.

### Tooling and documentation
- Testnet contributors program (`docs/19`): scoring from the blocks of the chain (`tools/testnet_rewards.py`), registration by message signature
  (`vearl-wallet sign` / `verify`, `tools/verify_registration.py`) and a public leaderboard page (`site/leaderboard/`).
- Independent Python implementations of the work layer, the chain, the market, tiled products, tensor programs, level 2 and ASERT, checked
  against frozen vectors.
- Specification, threat model, economics, miner guide and runbook in `docs/`.

### Known limits
See `docs/09` and `docs/13`: no external audit, selfish mining is not addressed, no finality gadget, the peer channel is not post-quantum,
a job that is claimed and never published expires without being reopened.
